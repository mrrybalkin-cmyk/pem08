# Demo guide

Сценарий для преподавателя: конкурент → источники → анализ → сводный профиль → сравнение. Приложение открывается в браузере; Swagger для основного сценария не нужен.

## Подготовка

1. Выполните [Quick Start](../README.md#quick-start--windows--powershell) с Python 3.14 и установленным Chromium.
2. Для нового AI-анализа заполните свой `AI_API_KEY` в локальном `.env`. Source creation, reanalysis, aggregate и comparison обращаются к провайдеру и могут тарифицироваться. Без ключа можно проверить запуск, карточки и сохранённые результаты, если они уже есть локально.
3. Запустите `python run.py` из корня проекта и откройте http://127.0.0.1:8000. Свежий clone имеет пустую DB; screenshots в README не являются импортированными demo-данными.

## Основной сценарий

1. Нажмите **Добавить конкурента**. Укажите название выбранной компании, её публичный сайт и нишу. Создайте вторую карточку для последующего сравнения.
2. В первой карточке нажмите **Добавить источник**. Для простого начала выберите Text, задайте понятное название и вставьте 10–30 000 символов из публичного описания продукта. Можно отдельно попробовать JPEG/PNG/WebP, PDF или публичный HTTP(S) URL.
3. Дождитесь завершения обработки. В источнике доступны сохранённое содержимое и metadata, справа — badge **Анализ отдельного источника**, ключевые выводы и оценки. Раскройте **Обоснование**, затем проверьте вкладки **Доказательства**, **Действия** и **Ограничения**.
4. Добавьте ещё один материал о компании и нажмите **Сводный анализ**. Badge **Сводный анализ конкурента** показывает объединённый профиль. **Последний сводный** открывает сохранённый результат без нового AI-запроса.
5. Добавьте хотя бы один источник второй компании и создайте её сводный анализ. Нажмите **Сравнить**, выберите две карточки и проверьте состояние **Готово к сравнению**. Только **Сравнить выбранных** запускает запрос.
6. Изучите матрицу общих критериев и ограничения результата. Сопоставляются предоставленные материалы; приложение не определяет объективно лучшую компанию.

## Что проверить дополнительно

- **Повторить анализ** использует текущий snapshot без capture. Для URL **Обновить страницу** создаёт новую версию страницы и analysis.
- История справа позволяет открыть старый analysis; результат предыдущего snapshot явно отмечен как исторический.
- Перезапустите сервер: карточки, snapshots и результаты останутся в локальной SQLite. История comparisons сохраняется в DB, но отдельного UI для повторного открытия comparisons пока нет.
- На mobile переходы **Конкуренты / Источники / Анализ** доступны сверху; пояснения и вторичные секции раскрываются по запросу.
- При provider failure используйте actionable error и retry; при отсутствии данных сначала создайте source analyses / aggregates. Не удаляйте данные для устранения ошибки провайдера.

Для бесплатной offline-проверки полного workflow с изолированными deterministic fixtures запустите `python -m tests.browser_ui_smoke` после установки `requirements-dev.txt`. Он не читает `.env`, не использует production DB и не вызывает OpenAI. Все команды проверки — в [README](../README.md#testing--verification).

Desktop PyQt6/PyInstaller packaging не входит в эту реализацию: сдаётся Web-first PEM08 v2.
